# Перевод OpenBlade

[English](../localization-translators.md) | [简体中文](../zh-CN/localization-translators.md) | Русский

Для перевода OpenBlade не нужны Visual Studio или опыт программирования.
Сопровождающие экспортируют один ZIP-файл с совместимым с Excel CSV и снимками экрана
на исходном языке. Вы редактируете один столбец и возвращаете CSV для автоматической
проверки.

<a id="for-translators"></a>
## Для переводчиков

1. Извлеките ZIP-файл и откройте `OpenBlade-<locale>.csv` в Microsoft Excel или
   LibreOffice Calc. Excel распознает кодировку UTF-8, поскольку файл содержит метку
   порядка байтов UTF-8.
2. Редактируйте только столбец **Translation**. Не переименовывайте столбцы, не меняйте
   ключи, не удаляйте строки и не редактируйте столбцы исходного текста, контекста и хеша.
3. Используйте **Context** и **Screenshots**, чтобы увидеть, где появляется текст. Пути
   к снимкам экрана указаны относительно извлечённой папки пакета. В **Constraints**
   перечислено всё, что должно остаться без изменений.
4. Сохраняйте без изменений такие элементы, как `{0}`, `{1:N0}`, теги разметки,
   идентификаторы моделей, URL-адреса и имена файлов. Сохраняйте намеренные пробелы в
   начале и конце и разрывы строк. Для сочетаний клавиш меню сохраняйте указанное число
   символов подчёркивания, но ставьте каждый из них перед подходящей буквой своего языка.
5. Заполните каждую ячейку Translation. Если перевод должен буквально начинаться с
   `=`, `+`, `-` или `@`, поставьте перед ним один символ табуляции. Он помечает значение
   как текст, а не формулу Excel; при проверке этот единственный служебный символ
   табуляции удаляется.
6. Сохраните файл как **CSV UTF-8 (Comma delimited)**. Верните CSV, а не
   преобразованный файл `.xlsx`. Сопровождающие проверят его перед открытием или импортом.

Сообщение проверки указывает раздел ресурсов и ключ, в которых найдена проблема.
Распространённые сообщения означают следующее:

- **stale or tampered**: изменился английский исходный текст, текущие целевые каталоги
  или структура пакета; запросите свежий экспорт и скопируйте переводы в его столбец
  Translation.
- **changed format placeholders**: восстановите каждый полный элемент, например `{0}`
  или `{1:N0}`. Элементы можно перемещать в соответствии с грамматикой.
- **changed markup/access-key/whitespace**: восстановите структуру разметки, число
  подчёркиваний сочетаний клавиш, разные буквы сочетаний для одновременно показанных
  действий либо намеренные пробелы и разрывы строк, указанные в Constraints.
- **formula character**: поставьте один символ табуляции перед допустимым начальным
  `=`, `+`, `-` или `@` либо удалите его, если он появился случайно.

<a id="for-maintainers"></a>
## Для сопровождающих

В новом рабочем дереве один раз восстановите зависимости обычного решения,
сборки для предпросмотра и теста снимков установщика без подключения к службам:

```powershell
dotnet restore OpenBlade.slnx -p:NuGetAudit=false
dotnet restore .\src\OpenBlade.Tray\OpenBlade.Tray.csproj `
    -p:NuGetAudit=false -p:OpenBladeLocalizationPreview=true
dotnet restore `
    .\build\installer\OpenBlade.Installer.UI.Tests\OpenBlade.Installer.UI.Tests.csproj `
    -p:NuGetAudit=false
```

Экспортируйте пакет из корня репозитория:

```powershell
.\build\Export-LocalizationTranslatorPackage.ps1 -Locale ru-RU
```

По умолчанию команда создаёт снимки заранее заданных экранов en-US в режиме
предпросмотра локализации без подключения к службам, записывает папку в `artifacts/localization/translator/` и
создаёт ZIP с отсортированными записями и фиксированными метками времени. Дочерние
средства визуализации используют локальный для процесса контекст совместимости 96 DPI,
фиксированную светлую тему, программную визуализацию установщика и очищенные примерные
данные. Снимки используют фиксированную палитру, подходящую для проверки,
чтобы безвредные различия сглаживания средства визуализации не меняли байты пакета.
В режиме снимков метаданные коммита сборки не показываются в отображаемой версии
приложения, поэтому инкрементальная сборка не может показать устаревшую ревизию в остальном
актуальном пакете. Этот профиль визуализации и хеш каждого изображения записываются в
манифесте пакета; системные параметры дисплея не меняются. Операция не устанавливает
OpenBlade, не запрашивает UAC, не запускает службу или Session Agent и не выполняет
аппаратные записи. Каталог результата игнорируется Git; не фиксируйте созданные CSV,
ZIP или PNG.

Если любое из средств визуализации без подключения к службам не получает стабильный
кадр за отведённые десять секунд, `Capture-LocalizationSnapshots.ps1` сохраняет последние
два канонических кадра в
`artifacts/translator-archive-failures/snapshot-stability/<culture>/<capture-id>/`
в подкаталогах раздела ресурсов, этапа и уникального идентификатора ошибки. Размер каждого кадра
ограничен 32 MiB. Полный набор данных об ошибке содержит `previous.bgra` и
`candidate.bgra`, а также `metadata.json` с размерами и SHA-256 каждого кадра;
`metadata.json` является маркером завершения, поэтому каталог без него содержит
частичные данные неудачной попытки сохранения. Такое сохранение применяется к процессам
создания снимков и экспорта переводчика, которые вызывают этот скрипт. Прямые запуски
средства локализации находятся за пределами настроенного процесса, а результат
`--capture` для строк производительности намеренно исключён из области захвата и
экспорта локализации. Успешная визуализация не создаёт каталог данных об ошибках.

Проверьте возвращённую рабочую книгу до её открытия:

```powershell
.\build\Import-LocalizationTranslatorWorkbook.ps1 `
    -Workbook C:\path\to\OpenBlade-ru-RU.csv `
    -ValidateOnly
```

Импортируйте её только после успешной проверки:

```powershell
.\build\Import-LocalizationTranslatorWorkbook.ps1 `
    -Workbook C:\path\to\OpenBlade-ru-RU.csv
```

Импорт восстанавливает текущую модель источника из всех четырёх определяющих каталогов.
Он принимает строки в изменённом порядке, но до записи отклоняет отсутствующие, лишние,
повторяющиеся, структурно неполные, устаревшие или изменённые строки. Рабочая книга также
привязана к точным файлам целевых каталогов, существовавшим при экспорте, поэтому новый
перевод нельзя незаметно перезаписать. Принятый импорт заново создаёт каждую локаль из
текущего определяющего набора исходных ключей, добавляет новые переведённые ключи и
удаляет устаревшие. Четыре исходных каталога остаются открытыми для чтения с запретом изменений от
восстановления модели до проверки и записи, поэтому одновременное изменение источника
не может обойти хеши рабочей книги. До проверки целевого хеша импорт также открывает все
четыре существующих целевых каталога с дескрипторами, запрещающими запись, а отсутствующие
файлы резервирует с семантикой создания нового файла. Эти дескрипторы сохраняются во
время промежуточной записи, проверки и отката. Поэтому одновременное сохранение в
редакторе завершается ошибкой вместо незаметной потери одной из версий. Импорт проверяет
полные элементы составного форматирования .NET, разметку, число клавиш доступа и
конфликты между одновременно видимыми действиями установщика, значимые пробелы, разрывы
строк, значения только из знаков препинания, защищённые технические идентификаторы,
управляющие и небезопасные символы формата Unicode, а также префиксы формул электронных
таблиц. Если запись или проверка локализации репозитория завершается ошибкой, все
затронутые каталоги восстанавливаются. Импорт никогда не меняет допуск языков или
упаковку; экспорт и импорт принимают только текущие допущенные рабочие локали `zh-CN` и
`ru-RU`. Добавление ещё одной рабочей локали остаётся отдельным проверяемым изменением.
`qps-ploc` всегда отклоняется как целевой язык переводчика и остаётся только для
разработки.

Пара `Surface + Key` служит постоянным идентификатором строки рабочей книги. Формат версии 2 назначает
каждой строке хеш SHA-256 её неизменяемых полей источника и контекста, повторяет хеш
исходного каталога по всем упорядоченным хешам строк и повторяет хеш целевого каталога
по точным четырём файлам локали, присутствовавшим при экспорте. Это детерминированные
индикаторы изменений, а не подписи; границей доверия служит новое сравнение импорта с
извлечёнными определяющими каталогами.

<a id="why-this-format"></a>
## Почему выбран этот формат

OpenBlade использует метку UTF-8 BOM и CSV в стиле RFC 4180 внутри детерминированного
ZIP вместо XLSX или XLIFF. CSV открывается в обычных программах электронных таблиц,
остаётся доступным для просмотра как текст, не требует двоичной рабочей книги с
поддержкой макросов и удобно сопоставляется с импортом, проверяемым в Git. XLIFF остаётся
более богатым отраслевым форматом обмена, но его процесс на основе XML и специальных
инструментов менее удобен для переводчиков без технической подготовки из задачи #274.

Проект опирается на следующие актуальные источники и сопоставимые процессы с открытым
исходным кодом:

- [Microsoft: правильное открытие CSV-файлов UTF-8 в Excel](https://support.microsoft.com/en-us/office/opening-csv-utf-8-files-correctly-in-excel-8a935af5-3416-4edd-ba7e-3dfd2bc4a032)
- [Microsoft: контекстные метаданные для локализации](https://learn.microsoft.com/en-us/globalization/internationalization/contextual-metadata)
- [Microsoft: составное форматирование .NET](https://learn.microsoft.com/en-us/dotnet/standard/base-types/composite-formatting)
- [Weblate: CSV-файлы](https://docs.weblate.org/en/latest/formats/csv.html),
  [проверки переводов](https://docs.weblate.org/en/latest/user/checks.html) и
  [снимки экрана для визуального контекста](https://docs.weblate.org/en/latest/admin/translating.html)
- [OASIS XLIFF 2.1](https://docs.oasis-open.org/xliff/xliff-core/v2.1/xliff-core-v2.1.html)
- [GNU gettext: записи PO](https://www.gnu.org/software/gettext/manual/html_node/PO-File-Entries.html)
  и [контексты сообщений](https://www.gnu.org/software/gettext/manual/html_node/Contexts.html)
- [Стандарт безопасного хеширования NIST FIPS 180-4](https://csrc.nist.gov/pubs/fips/180-4/upd1/final)
- [OWASP: внедрение в CSV](https://owasp.org/www-community/attacks/CSV_Injection)
- [Mozilla Pontoon](https://github.com/mozilla/pontoon) — сопоставимый процесс с открытым
  исходным кодом, работающий с репозиторием и предоставляющий интерфейс переводчикам без технической подготовки.

Обработка устаревания в OpenBlade строже, чем в gettext/Weblate. Устаревшие рабочие
книги отклоняются, поскольку четыре отдельно поставляемых набора ресурсов должны
оставаться полными и синхронизированными; они никогда не импортируются как неточные
переводы.
