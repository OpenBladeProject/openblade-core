# Файлы подсветки клавиатуры OpenBlade

[English](../keyboard-lighting-file-format.md) | [简体中文](../zh-CN/keyboard-lighting-file-format.md) | Русский

Файлы подсветки клавиатуры OpenBlade — это документы JSON в кодировке UTF-8 с
расширением `.oblight`. Версия 1 хранит один переносимый пресет эффекта клавиатуры.
Импорт пресета никогда не предоставляет аппаратную возможность: эффект уже должен быть
допущен для точной модели подключённого Blade и его микропрограммы.

Импорт файлов подсветки клавиатуры является экспериментальной функцией. Включите
**Функции Lab** в параметрах OpenBlade, чтобы показать импорт на странице
«Подсветка». Если позже отключить функции Lab, импорт новых файлов будет скрыт,
но уже активный или сохранённый в профиле питания эффект не отключится. Импорт принимает
эффекты, поддерживаемые вашей моделью. [Экспериментальные настройки ноутбука](experimental-blade-support.md)
включаются автоматически и не зависят от функций Lab.

Тип носителя: `application/vnd.openblade.keyboard-lighting+json`.

Формат содержит только данные. Он не может включать скрипты, подключаемые модули,
внешние ресурсы, пути к файлам, идентификаторы USB, отчёты HID, команды микропрограммы
или сопоставления устройств. OpenBlade отклоняет неизвестные поля, повторяющиеся поля,
недопустимые значения перечислений, неподдерживаемые версии схемы и файлы размером
более 64 KiB.

<a id="example"></a>
## Пример

```json
{
  "format": "openblade-keyboard-lighting",
  "schemaVersion": 1,
  "metadata": {
    "name": "Northern lights",
    "author": "Example",
    "description": "A two-color breathing preset.",
    "revision": 1
  },
  "effect": {
    "kind": "breathing",
    "brightnessPercent": 70,
    "colorMode": "dual",
    "primaryColor": "#47E10C",
    "secondaryColor": "#8A2BE2"
  }
}
```

Полный пример находится в файле
[`docs/examples/northern-lights.oblight`](../examples/northern-lights.oblight).
Для движущегося пресета файл
[`docs/examples/slow-fade-sweep.oblight`](../examples/slow-fade-sweep.oblight)
использует яркую голубую волну вправо с тусклым синим следом.
Нормативная структура находится в файле
[`docs/schemas/openblade-keyboard-lighting-v1.schema.json`](../schemas/openblade-keyboard-lighting-v1.schema.json).
Семантическая проверка среды выполнения остаётся определяющей.

<a id="envelope"></a>
## Конверт

| Поле | Требование |
| --- | --- |
| `format` | Должно иметь значение `openblade-keyboard-lighting`. |
| `schemaVersion` | Должно иметь значение `1`. Будущие версии отклоняются с понятным сообщением. |
| `metadata.name` | Обязательно; 1–80 символов после удаления пробелов по краям. |
| `metadata.author` | Необязательно; `null` или 1–80 символов. |
| `metadata.description` | Необязательно; `null` или 1–500 символов. |
| `metadata.revision` | Положительное целое число, выбранное автором пресета. |
| `effect` | Один объект эффекта из таблицы ниже. |

Цвета используют запись sRGB `#RRGGBB`. Для каждого эффекта, кроме `off`, требуется
`brightnessPercent` от 1 до 100.

<a id="effects"></a>
## Эффекты

Имена эффектов следуют терминологии Razer Chroma, когда совпадает семантика, и
дополняются допущенными эффектами OpenBlade, формируемыми на компьютере.

| `kind` | Дополнительные поля |
| --- | --- |
| `off` | Нет. |
| `static` | `color`. |
| `spectrumCycling` | Нет. |
| `breathing` | `colorMode`: `single`, `dual` или `random`; соответствующие допускающие null поля `primaryColor` и `secondaryColor`. |
| `reactive` | `color`; `duration`: `short`, `medium` или `long`. |
| `tidal` | `primaryColor`, `secondaryColor`, `randomColors` и `direction`. |
| `starlight` | `colorMode`, соответствующие цвета и `duration`. |
| `wave` | `direction`: `leftward` или `rightward`. |
| `wheel` | `direction`: `clockwise` или `counterclockwise`. |
| `ripple` | `color`. |
| `ambientAwareness` | `region`: `full`, `left`, `top`, `right` или `bottom`. |
| `audioMeter` | `colorBoost` от 1 до 4 с шагом 0.25; `decayMilliseconds` от 0 до 2000 с шагом 250 ms. |
| `fire` | Нет. |

Импортированный пресет применяется через ту же типизированную операцию службы, что и
ручное изменение на странице «Подсветка». В окне подтверждения указано, что он будет
применён, а результат останется несохранённым изменением активного профиля питания,
пока пользователь не сохранит или не отменит его. Файл не меняет подсветку логотипа
на крышке.

<a id="razer-chroma-compatibility"></a>
## Совместимость с Razer `.chroma`

[Редактор Chroma от Razer под лицензией MIT](https://github.com/razerofficial/CChromaEditor/blob/6ce8b24db8e4e00ddafe027de7589b2a0b4dc618/LICENSE),
его [сериализатор двоичного формата `.chroma`](https://github.com/razerofficial/CChromaEditor/blob/6ce8b24db8e4e00ddafe027de7589b2a0b4dc618/CChromaEditorLibrary/Animation2D.cpp#L370-L461)
и [соответствующее средство чтения](https://github.com/razerofficial/CChromaEditor/blob/6ce8b24db8e4e00ddafe027de7589b2a0b4dc618/CChromaEditorLibrary/ChromaSDKPlugin.cpp#L1142-L1356)
служат основными источниками совместимости. Они предоставляют удобные кадры анимации
на фиксированной сетке и длительность каждого кадра, а Razer описывает последовательную
визуализацию на клиенте. Однако двоичный контейнер не содержит сигнатуры формата,
встроенных размеров сетки, идентификатора раскладки, конверта метаданных или схемы.
Его универсальная канва клавиатуры также не подтверждает проверенное сопоставление с
точным порядком протокола любой из двух моделей OpenBlade.

Импорт принимает официальные двоичные файлы версии 1 с типом устройства `2D` и
устройством `Keyboard` (6×22) или `KeyboardExtended` (8×24). Он проверяет полную
структуру little-endian, число кадров, конечные положительные длительности, значения
Win32 `COLORREF`, точную длину и предельный размер 5 MiB. Он никогда не загружает
Chroma SDK или Synapse.

Одноцветные файлы не зависят от раскладки: полностью чёрные входные данные превращаются
в `off`, а любой другой единственный цвет — в `static` со 100% яркостью. Преобразование
выполняется без потерь, даже когда источник содержит несколько одинаковых кадров.

Файлы `Keyboard` с подсветкой отдельных клавиш принимаются на отдельно проверенных
раскладках RZ09-0581 и RZ09-0528. Адаптер начинает с официальной
[сетки именованных клавиш Razer](https://github.com/razerofficial/CChromaEditor/blob/6ce8b24db8e4e00ddafe027de7589b2a0b4dc618/CChromaEditorLibrary/RzChromaSDKTypes.h#L173-L300),
а затем проецирует только те логические клавиши, целевая позиция которых уже допущена
для этой точной модели. Он не сжимает универсальную канву с 22 столбцами в кадр
протокола Blade с 17 столбцами и никогда не заимствует карту позиций одной модели для
другой. Это важно для таких клавиш, как Right Alt, чья допущенная позиция в протоколе
различается между двумя моделями.

Это преобразование логических клавиш намеренно не заявляется как полностью идентичное
Synapse. Если источник окрашивает ячейки без допущенного соответствия на ноутбуке, окно
подтверждения сообщает, сколько из них будет пропущено. Анимация отдельных клавиш
`KeyboardExtended` отклоняется, поскольку её канва 8×24 включает зоны мультимедиа и
настольной нижней подсветки без допущенной проекции Blade. Одноцветные файлы
`KeyboardExtended` по-прежнему поддерживаются.

Полученная анимация нормализуется в типизированную последовательность только с данными,
которой владеет служба. Она сохраняется вместе с профилем питания и продолжает работать,
когда приложение в области уведомлений закрыто. Последовательность ограничена 1 800
исходными кадрами, 1–60 000 ms на кадр, общей длительностью 10 минут и 4 096 байтами
декодированной дельты. Служба формирует изображение через существующую допущенную
операцию матричного кадра; импортированный файл не может предоставлять отчёты HID,
команды, идентичности или сопоставления.

Строгий JSON остаётся каноническим форматом обмена для нативных пресетов. Схема
`.oblight` версии 1 описывает встроенные типизированные эффекты; импортированные
последовательности Chroma не меняют эту схему и нормализуются в ограниченное состояние
профиля. Будущая схема `.oblight` сможет предоставить ту же модель последовательности,
сохраняя смысл версии 1.

Другие форматы повлияли на проектирование, но не являются безопасными готовыми
стандартами для подстановки:

- [Последовательности Polychromatic](https://docs.polychromatic.app/config/effects/sequence/)
  используют кадры JSON и циклическое воспроизведение, но их сопоставление имён
  устройств не является свидетельством допуска OpenBlade.
- [Профили OpenRGB](https://gitlab.com/CalcProgrammer1/OpenRGB/-/blob/release_candidate_1.0rc3/ProfileManager.cpp)
  — двоичные снимки устройств, связанные с идентичностью контроллера и версиями SDK.
- [QMK RGB Matrix](https://docs.qmk.fm/features/rgb_matrix) хорошо разделяет матрицу,
  светодиоды и физические позиции, но пользовательские эффекты представляют собой
  скомпилированный код C.
- [Lightscripts SignalRGB](https://docs.signalrgb.com/developer/) — исполняемые HTML и
  JavaScript, которые находятся за пределами допуска этого импорта.
- [Динамическое освещение Windows](https://learn.microsoft.com/en-us/windows-hardware/design/component-guidelines/dynamic-lighting-devices)
  стандартизирует устройства HID LampArray, а не переносимый файл эффектов.

<a id="compatibility-and-versioning"></a>
## Совместимость и управление версиями

Значение `schemaVersion` файла не зависит от версий хранилища профилей OpenBlade и IPC.
Средства чтения версии 1 никогда не переосмысливают неизвестный будущий документ.
Добавление нового необязательного или обязательного поля, вида эффекта, модели кадров
или целевой раскладки требует нового изолированного средства чтения схемы, если прежний
смысл невозможно сохранить в точности.
