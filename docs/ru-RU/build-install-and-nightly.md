# Сборка, установка и выпуски Nightly

[English](../build-install-and-nightly.md) | [简体中文](../zh-CN/build-install-and-nightly.md) | Русский

Этот документ описывает публикацию рабочих сборок, установку, восстановление и
процесс выпуска Nightly. Для обычной сборки из исходного кода используйте команды
из [руководства разработчика](../developer-guide.md#build-and-test).

<a id="publish-artifacts"></a>
## Публикация артефактов

Создайте графический установщик, рабочий комплект `win-x64` и отдельные
инструменты разработчика:

```powershell
.\build\Publish.ps1
```

- Графический установщик: `artifacts\win-x64\OpenBlade-Setup.exe`
- Распакованный рабочий комплект и программа установки для командной строки:
  `artifacts\win-x64\OpenBlade`
- Инструменты разработчика: публикуются отдельно тем же скриптом

Установленные приложения используют общесистемную 64-разрядную среду .NET 10
Desktop Runtime. Если совместимая среда отсутствует, графический установщик
предложит скачать и установить её до замены OpenBlade. Visual C++ и Windows App SDK
по-прежнему входят в комплект. Программа установки и инструменты разработчика
остаются самодостаточными.

Общая среда выполнения должна быть стабильным исправлением 10.0 не ниже
опубликованной минимальной версии. Установщик использует 64-разрядное расположение,
зарегистрированное в 32-разрядном представлении реестра, как это делает .NET apphost.
Перед подготовкой обновления он проверяет выбранную Desktop Runtime и объявленную ею
зависимость от основной среды выполнения. Восстановление OpenBlade не меняет уже
установленную общую среду выполнения.
Если выбранная общая среда повреждена, восстановите эту версию с помощью установщика
Microsoft .NET 10 Desktop Runtime, а затем повторите установку OpenBlade.

Чтобы создать автономный установщик, запустите `build/Publish.ps1 -OfflineInstaller`.
Он включает ту же проверенную зависимость .NET. Используйте этот вариант для пакета
Microsoft Store.

Подписание выпуска при разработке необязательно. Для общедоступной подписанной сборки
передайте отпечаток сертификата в `Publish.ps1`. Скрипт сначала подписывает файлы
OpenBlade до их включения в WiX, затем подписывает отделённый движок Burn и итоговый
установщик.

<a id="interactive-installation"></a>
## Интерактивная установка

- Дважды щёлкните `OpenBlade-Setup.exe` и выберите **Установить**. Windows запросит
  разрешение администратора только тогда, когда установщик будет готов изменить систему.
- Установщик следует теме приложений Windows. Во время установки, восстановления или
  удаления выберите **Показать подробности**, чтобы увидеть изменяемые файлы, записи
  реестра, ярлыки и службы.
- После успешной установки или восстановления выберите **Запустить OpenBlade**.
  Приложение в области уведомлений запустит Session Agent, и оба процесса будут работать
  в обычном пользовательском сеансе.
- Не запускайте установщик командой **Запуск от имени администратора**. В этом случае
  приложение в области уведомлений и Session Agent унаследуют повышенные права. Если
  это произошло, закройте их и запустите OpenBlade обычным способом.

<a id="quiet-installation"></a>
## Тихая установка

- При тихой установке не показывается интерфейс установщика и не запускается приложение.
- После успешного завершения `/quiet` вызывающая система автоматизации должна запустить
  установленный `OpenBlade.Tray.exe` из исходного процесса с обычным уровнем целостности
  и подтвердить, что приложение в области уведомлений и Session Agent работают.
- Такой перезапуск под управлением вызывающей стороны не применяется к EXE-каналу
  Microsoft Store, поскольку тихим запуском управляет Partner Center. Оставшийся пробел
  отслеживается в [задаче #25](https://github.com/OSSBlade/openblade-core/issues/25).

<a id="versioned-development-builds"></a>
## Версионируемые сборки для разработки

Используйте монотонно возрастающую ревизию Nightly, когда устанавливаете несколько
точных сборок для разработки без изменения основной версии продукта:

```powershell
.\build\Publish.ps1 -BuildChannel Nightly -BuildRevision 42 -SourceRevision (git rev-parse HEAD)
```

- Если интерактивный установщик находит ровно один кэшированный комплект той же версии,
  он предлагает **Восстановить**, чтобы заменить установленные файлы входящим комплектом,
  или **Удалить**, чтобы выполнить путь удаления установленного комплекта с сохранением
  профилей. При восстановлении сохраняется постоянный токен владения для каждого
  комплекта, поэтому даже предшественник, собранный из той же ревизии, не сможет удалить
  новый комплект. Чтобы удалить и сохранённые профили, закройте входящий установщик,
  удалите зарегистрированную запись OpenBlade через «Установленные приложения» Windows
  и выберите там **Удалить сохранённые профили и параметры**.
- Тихая команда `/install` по-прежнему считает равную версию конфликтом, поскольку не
  может выбрать действие обслуживания от имени пользователя. Для автоматического
  обслуживания явно используйте `/repair` или `/uninstall`.
- Для каждой проверки точной сборки используйте более высокую ревизию Nightly. Не
  устанавливайте разные артефакты Stable с одной и той же версией продукта.

<a id="duplicate-bundle-registrations"></a>
## Повторяющиеся регистрации комплектов

Установщик останавливается до этапа Apply, если обнаруживает несколько связанных
регистраций комплектов OpenBlade. Старые установщики могут рекурсивно запускать друг
друга при удалении Burn и заблокироваться.

- Защита также действует для смешанного набора из одной старой и одной новой регистрации,
  поскольку в этом случае нет единственного предшественника для замены.
- Интерактивный установщик сообщает о конфликте после обнаружения и не предлагает
  установку или восстановление.
- Если установщик предлагает удалить собственный зарегистрированный комплект, сначала
  используйте этот вариант.
- Перед повторным запуском нового установщика удалите оставшиеся повторяющиеся записи
  через восстановление установщика Windows.

<a id="command-line-setup-and-recovery"></a>
## Установка и восстановление из командной строки

Распакованный рабочий комплект остаётся доступен в
`artifacts\win-x64\OpenBlade` для разработки и восстановления. При необходимости
запускайте его установщик из терминала с повышенными правами. Для отдельной установки
общесистемная .NET Desktop Runtime уже должна быть установлена; чтобы получить её,
используйте графический установщик:

```powershell
.\artifacts\win-x64\OpenBlade\OpenBlade.Setup.exe install
```

Удаляйте OpenBlade через Параметры Windows или повторно запустите графический установщик.
Оба варианта сохраняют профили и предпочтения. Отдельный установщик также поддерживает
`uninstall --purge`, чтобы удалить сохранённые данные, если установка принадлежит ему.

Если графический установщик утрачен, но его маркер владения остался, выполните:

```powershell
.\artifacts\win-x64\OpenBlade\OpenBlade.Setup.exe uninstall --recover-orphaned-bundle
```

<a id="microsoft-store-channel"></a>
## Канал Microsoft Store

- Будущая EXE-публикация в Microsoft Store использует описанную выше автономную сборку.
- Установки из Store используют `/install /quiet /norestart`; прямые загрузки сохраняют
  графический интерфейс.
- Вызывающая сторона Store не может выполнить требуемый после тихой установки
  перезапуск с обычным уровнем целостности, поэтому поддержка жизненного цикла останется
  неполной до решения [задачи #25](https://github.com/OSSBlade/openblade-core/issues/25).

Контракт пакета, заметки о сертификации, раскрытие сведений об оборудовании и оставшиеся
внешние этапы выпуска описаны в документе
[«Публикация в Microsoft Store»](../microsoft-store-submission.md).

<a id="nightly-workflow"></a>
## Процесс Nightly

- Процесс GitHub Actions `Nightly` каждый день в 09:17 UTC собирает последнюю
  зафиксированную версию `main`; его также можно запустить вручную.
- Он выполняет применяемые в CI проверки форматирования, сборки, тестов, подготовки и
  рабочей публикации, а затем хранит артефакт Actions 14 дней.
- Каждая успешная сборка подготавливает черновой предварительный выпуск GitHub с
  установщиком, контрольной суммой, метаданными и снимком журнала изменений из точного
  коммита сборки.
- Процесс также открывает или обновляет черновой запрос на включение изменений в
  документацию, который записывает отсутствующие границы Nightly и сохраняет более
  новые записи `Unreleased` из `main`.
- Проверьте и объедините запрос с журналом изменений, затем запустите **Finalize Nightly**
  в `main` с точным тегом черновика. Перед публикацией черновика эта операция проверяет
  ресурсы и объединённый журнал изменений.
- Опубликованные сборки Nightly появляются на странице Releases. Приложение предлагает
  их только при выборе канала обновлений **Nightly**.

Nightly — тестовые сборки. Перед установкой проверьте `OpenBlade-Setup.exe` по
приложенному файлу SHA-256. Чтобы помочь с тестированием ноутбука, посмотрите доступные
настройки и правила отчётов в
[руководстве по экспериментальной поддержке Blade](experimental-blade-support.md).
На распознанных моделях настройки включаются автоматически в каждом канале обновлений.

<a id="attestations-and-signing-status"></a>
### Аттестации и состояние подписи

Происхождение сборки GitHub необязательно, поскольку аттестации артефактов доступны не
для каждого уровня видимости репозитория и тарифного плана. После подтверждения поддержки
сопровождающие могут установить `OPENBLADE_ENABLE_ATTESTATIONS` в `true` и проверить
включённую аттестацию командой:

```powershell
gh attestation verify .\OpenBlade-Setup.exe --repo OSSBlade/openblade-core
```

Включённый JSON определяет точный коммит, порядковую версию Nightly, время сборки,
запуск процесса, хеш установщика и состояние Authenticode. Если процесс не подключён к
защищённому сертификату подписи выпусков, для установщика ожидается состояние
`NotSigned`, а Windows может показать предупреждение о неизвестном издателе.

<a id="changelog-publication"></a>
### Публикация журнала изменений

- Для задачи журнала изменений требуется параметр репозитория **Allow GitHub Actions to
  create and approve pull requests**.
- В этой задаче доступ токена ограничен содержимым репозитория и запросами на включение
  изменений.
- Если параметр отключён, включите его и повторите неудавшуюся задачу журнала изменений.
  Выпуск останется черновиком, пока журнал изменений не будет объединён и проверен.
- Ошибки создания или прикрепления журнала изменений останавливают подготовку.
  Завершение также останавливается, если снимок исходного кода, объединённый раздел,
  ссылка сравнения или ресурсы не совпадают. Исправьте указанную проблему и завершите
  тот же черновой тег.
- Для размещаемой и локальной публикации используется `build/Complete-NightlyRelease.ps1`.
  Чтобы проверить подготовленный черновик без публикации, используйте `-VerifyOnly`.
