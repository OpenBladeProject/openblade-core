# Windows mailbox correction stage

This offline stage corrects managed transport handoff and native thermal observation. Default Windows roles remain managed and the required Rust core stays active. Service and Agent IPC versions are unchanged. Native mutations and full backend parity are separate work.

## Transfer evidence and recovery

Each v2 request has an immutable selection, original run and signed-build binding, request, actual quiescence receipt, retained-original exit record, epoch-binding intent, mapping, native proof and terminal publication. The transfer stays fenced until its exact evidence permits cancellation before native use or consumed-and-retired resolution. Recovery compares or completes the same records; it never deletes history, changes an old receipt's epoch or infers retirement from a missing file.

Native resolution authenticates retained packages, permanent reservations, origin and startup policy, every original attempt and its required drain, and owner retirement under custody. An unselected preparation needs a complete authenticated prefix, no admitted attempt or possible submission, and exclusion from every selection frontier. Other partial or unknown preparations remain fenced. Native binding follows origin/policy/custody creation, so its immutable intent can reconcile either mapping-publication half.

An intact legacy v1 mapping can receive a separate terminal envelope for the reviewed ffc20060/e7531d11 contract. That signed Setup recipe positively observed the retained managed original's exit before receipt binding. Recovery binds this historical contract to the unchanged run, signed predecessor package, enrollment, receipt, both original mapping copies and fresh native custody proof. It creates no new OS exit observation, receipt, drain or Retired record. Unmapped, incomplete, unsupported-source or unmatched legacy records remain fenced. Every original v1 byte is retained.

Renewal requires proven native retirement, an authenticated new managed run and original process, then a new request and receipt for a fresh epoch. Direct native-to-native renewal is not admitted.

## Managed availability and enrollment

Optional v2 handoff storage is created below the installer-protected OpenBlade machine-data namespace. A protected parent creation intent precedes child creation; completion precedes run history. Exact interrupted bootstrap prefixes can finish while preserving publication residue. Unknown children are refused without adoption or erasure. Optional storage failures are separate from mandatory native-custody admission.

Managed startup acquires managed exclusion before ending its completed native proof leases. A new native reader still needs a new authenticated transfer and SCM original. First enrollment uses a separate protected creation mutex and positively unenrolled checks before mutation. Replacement and removal retain managed, legacy and native maintenance custody throughout changes.

Setup waits for the already-retained original using a cancellable monotonic budget. Exit, timeout, cancellation and wait errors remain separate from receipt and drain evidence. SCM Stopped never substitutes for original exit or transport retirement.

## Diagnostic status and retention

The production status composition distinguishes an acquired reader from an origin-authenticated attempt that never constructed a firmware worker. The latter serves GetStatus and subscriptions. Its stop certifies only its own transport work after listener/metadata drain; earlier attempts and acquisition records remain untouched. Observation artifacts still require transport drains.

Read permission loss is sticky. Mapping recovery does not reconnect a worker or restore read authority. Valid-origin metadata continues with unavailable or revoked presentation; actual origin loss remains fatal. Faulted workers retain custody and discard late results.

Last confirmed thermal presentation is retained for five monotonic seconds from successful getter completion. Both caller projections label retention and use current identity, access, power and controller metadata. Metadata refresh does not renew age or copy stale deviceVerified. At expiry, thermal presentation becomes unavailable. Retained values have no fresh-read witness, capabilities or write authority.

## Owner retirement

Existing guarded keyboard/fan lifecycle cleanup stays before owner retirement. Remaining legitimate owner close runs before final admission sealing and is tracked separately from bounded disposal waiters. Caller timeout does not cancel ownership bookkeeping or mint a receipt. Actual port/provider tasks and their owners remain rooted on timeout or failure; late completion cannot publish a receipt. Ambiguous keyboard release is not replayed during close on either shared validated lighting backend.

## Verification boundary

This stage permits cached offline compilers, ordinary unit harnesses, pure/injected/private-filesystem fixtures and static PE inspection. Rust tests use a preserved exact-name allowlist after listing. Role, process, token, session, SCM, task and private-pipe probes are excluded. Role/AOT images are compiled and inspected as bytes only. No installed role, hardware command, installation, UAC, sleep/resume, network, push, PR or release is part of this stage.

The full Windows replacement still includes all 53 Service kinds, 17 Agent forms, Custom 0D/87, mutations, configuration, profiles, durable journals, background automation, lifecycle behavior, other backends/models and default cutover, followed by separately authorized runtime and physical proof. Linux, macOS and SwiftUI remain deferred.
