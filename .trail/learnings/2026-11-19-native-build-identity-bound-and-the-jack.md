The `.obid` build identity was bounded at 1024 bytes in four places (build.rs assert, `compiled_record`, `inspect_artifact`, managed `NativeArtifact.Inspect`), and the worst shippable composition (service-temporary-charge-v1 plus all six Agent features, release) reached 977. It is now 4096, stated once per language: `MAX_IDENTITY_BYTES` in `tools/openblade-windows-host/src/native_package/identity_bound.rs`, a `#[path]` module of both build.rs and native_package.rs, and `NativeArtifact.MaximumIdentityBytes` in C#. It is a module rather than an `include!` so that `cargo fmt --all --check` reaches it (an `include!`d file is never formatted). build.rs names it only in its assert, path-qualified (`identity_bound::MAX_IDENTITY_BYTES`), in the condition and in the message. `the_identity_bounds_match_the_managed_and_build_script_bounds` pins the C# constants, the module declaration, every occurrence of `identity_bound`, `#[path` and the bound, and both texts. That is a text check: it catches a second module, import or binding of that name written in build.rs, including a block-scoped `#[path]` mount, but not a name brought in by a macro or `include!`, or a cfg-dependent definition inside identity_bound.rs.

The `.obid` cap was not the only bound. The package record carries each artifact record (identity + size + digest + imports) as base64, and that field was capped at 2048 characters by the general `NativeCanonical.Lines` field bound in C# and at 4096 by `decode64` in Rust. With the measured imports, that capped the Agent identity near 1259 bytes, so raising only the `.obid` cap would have moved the failure into `WindowsNativePackage`'s constructor. Both languages now share `MaximumRecordBase64` / `MAX_ARTIFACT_RECORD_BASE64` = 10924 (base64 of up to 8193 bytes). Any future identity growth has to check this whole chain: identity, artifact record field bound, package base64 field bound, and the 16384-byte package total.

The managed limits are per field, in `NativeCanonical.FieldMaximum`: only NativeArtifactRecord.v2 Features (index 4) and Capabilities (index 10), the identity lines without a tighter check in Inspect, widen to `MaximumIdentityBytes`, and only NativePackage.v2 fields 8 and 9 (the Service and Agent records) widen to `MaximumRecordBase64`. Imports (not identity content: Rust recomputes it from the image), every other field and v1 records keep 2048; build.rs emits only v2. `RecordFieldsAdmitTheirLimitAndNoMore` covers every index of both v2 headers and the v1 artifact record from one table. `MaximumRecordBytes` is pinned on both edges by its base64 length, because 8191 to 8193 bytes all encode to 10924 characters. `NativeArtifact.Encode` refuses a record over `MaximumRecordBytes` (8193), so it never produces one the package field must refuse; only a hand-built artifact reaches that, since an identity at the bound with 2048-character imports is about 6.2 KB. Rust has no per-field limits: it only reads records the managed encoder wrote, and its package decode stops at the same 10924 characters, and only for fields 8 and 9; `decode64` keeps 4096 and a test asserts it refuses both package fields.

Both Rust package readers (`read_package`, and `historical_battery_producer`, which is bypassed under cfg(test)) parse through `package_record`, which decodes fields 8 and 9. That made the decode bound testable: before, reverting either call site to `decode64` survived every test. The historical path now also decodes the Agent record it ignores, which is stricter only on an already authenticated package.

Measured from bound release images built from this change (parsed, never run): Agent identity 977 bytes, record 1254, base64 1672, imports 198 characters; Service identity 927, record 1188, base64 1584. With both identities at 4096 the package is about 12159 of 16384 bytes, so the package total is not the binding limit; the identity has 3119 bytes of headroom, roughly 44 more Agent capabilities at about 70 bytes each.

`native-identity-bound-v1.json` holds inert PE headers with identities at 1025, 4096 (Agent and Service) and 4097 bytes; both languages check the same bytes. `identity_bound_data()` in native_package/tests.rs generates it from `MAX_IDENTITY_BYTES`, and `identity_bound_data_is_the_generator_output` fails until it is regenerated after a bound change: `cargo test --manifest-path tools/openblade-windows-host/Cargo.toml --lib regenerate_identity_bound_data -- --ignored`. The test helper `bytes()` decodes through `decode64`'s 4096-character bound, so larger KAT values need `decode64_bounded`.

Compatibility: bounds only widened, so every record an old reader wrote still parses. A record or image written under the new bounds and larger than the old ones is refused, fail closed, by an older reader (Setup's cleanup or selection, or an older host's `read_package`). Nothing native has shipped, so no installed or retained epoch is affected.
